## Privacy practices

### Single-purpose description

Improve the Zoho CRM developer and admin workflow: Deluge editor themes, indent guides, syntax
highlighting, cross-function search, and optional paid tools to export functions to local files,
search all workflow rules, and map how automations connect.

### Data usage checkboxes

Select these categories:

- **Personally identifiable information: Yes.** Email address for the optional account. The
  website also processes the account name; the extension itself receives neither email nor name.
- **Authentication information: Yes.** Opaque OAuth access and rotating refresh tokens, kept in
  trusted local extension storage, never synced. Authorization code, PKCE verifier and refresh
  token are sent only to the account API for authentication. Website passwords/session records
  stay in the website account flow; the extension never receives the password.
- **Location: Yes.** Ordinary connection IP address received by the account API when requests
  reach it. No GPS, geolocation permission or location tracking is used.

Leave Health information, Financial and payment information, Personal communications, Web
history, User activity and Website content unchecked for the extension. Card/payment details
are handled by Stripe through the separate website checkout; the extension does not receive
or transmit them. It receives only plan/entitlement status and relevant dates.

Website content and Zoho data are **not collected by our service**. Search, export, Search All
Workflows read function, workflow and related automation configuration
directly from the user's own Zoho org (Automation Map, which is coming soon and gated in this
version, reads nothing until it is released). Their caches stay locally in the browser; exports are local
files. Zoho cookies, credentials, org/CSRF context, records and
function code are never sent to our account service or Stripe. There is no analytics, browsing
history collection, click tracking or advertising identifier collection.

### Fetch audit — all production requests in src/

`src/billing/client.ts` owns the worker fetch wrapper; paths/client id come from
`src/billing/product-contract.json`. All account requests use credentials omitted and reject
redirects. Each connection also exposes the ordinary source IP address to its destination.

| Destination and method | Data sent and purpose |
| --- | --- |
| `https://api.devtools.zsetup.com/v1/auth/oauth2/token` — POST | Form fields `client_id`, `grant_type`; code exchange adds `code`, `redirect_uri`, `code_verifier`; refresh adds `refresh_token`. Receives OAuth tokens for optional sign-in. No Zoho data or cookies. |
| `https://api.devtools.zsetup.com/v1/entitlement` — GET | `Authorization: Bearer <access token>` to read plan, entitlement and dates. No cookies, email or Zoho data. |

| Current Zoho origin `/crm/v2/settings/functions` — GET | `type=org`, `start`, `limit` query fields; Zoho session cookies, `X-Crm-Org`, `X-Zcsrf-Token`, JSON Content-Type header. Lists functions for search/export. |
| Current Zoho origin `/crm/v2/settings/functions/<encoded-id>` — GET | Function id, `language`, `source`; same Zoho cookies/headers. Reads function metadata/source for search, preview, editor handoff and export. |

Read-only configuration for Search All Workflows (`src/content/workflows`, `src/content/zoho/workflows-page.ts`) and Automation Map (`src/content/automation-map/data`; gated and inactive in 2.4.0, ADR 0035). `src/content/functions/api.ts` implements both function fetches. `function-store.ts` and `overlay.ts`
call those helpers. `export-loader.ts` wraps the same fetches with cancellation/timeouts and
validation; it introduces no destination or payload. No other
production fetch, XMLHttpRequest, WebSocket or sendBeacon call exists in `src/`.

Browser-generated CORS preflights accompany account requests as needed. Normal-tab OAuth
navigation to `/v1/auth/oauth2/authorize` sends public client id, response type, exact extension
redirect URI, scopes, random state and S256 PKCE challenge/method. Website account, pricing,
privacy and support links, and the optional AI Assistant Chrome Web Store link, are navigations,
not fetch calls. The callback returns a code/state/issuer to the packaged extension page.
No remote JavaScript is loaded by the extension.

### Permission justification

**storage:** Save editor preferences and promotion dismissal/snooze state in Chrome sync
storage. Save account/notice state, OAuth tokens and expiry/refresh journal, a five-minute
entitlement cache and per-org function and workflow search caches locally; the background
worker keeps a bounded Automation Map cache in extension IndexedDB (gated and unused in 2.4.0). Credential storage is restricted
to trusted extension contexts; content scripts access only the separate function-cache channel.
Temporary OAuth transaction state uses trusted session storage.

**Background service worker:** Packaged Manifest V3 worker owns OAuth/token operations,
entitlement requests and local cache messaging. `background` is a manifest entry, not an
additional permission. The only declared permission remains `storage`, unchanged from 2.3.0.
There are no required or optional host permissions, identity, tabs, alarms or downloads
permissions. Zoho content-script matches remain unchanged. The packaged OAuth callback is
web-accessible only to the two first-party HTTPS origins; this adds no host permission.

**Remote code:** No, I am not using remote code. All executable extension code is packaged.
The API returns tokens and entitlement data, not executable code. Deluge source is displayed
or downloaded as data and is not executed by the extension.

## Reviewer test instructions

Use Chrome 116 or newer. A Zoho CRM account with access to Setup → Developer Hub → Functions
is required for editor, search and export features. Reviewers can create a free Zoho CRM trial:
https://www.zoho.com/crm/signup.html
Use an org with at least one test Deluge function to inspect downloaded content.

Free features: while signed out of DevTools, open Zoho CRM and check editor themes, indent
guides, syntax highlighting and Search All Functions. No DevTools account or payment is needed.

Paid features: sign up from the extension popup (Start free trial) — every new account gets a
14-day Plus trial automatically, no card; then open Zoho CRM → Setup → Developer Hub → Functions,
click Export. Sign-in opens a normal browser tab through https://api.devtools.zsetup.com using
OAuth with PKCE. Complete account registration/verification and return to Zoho after the
callback confirms sign-in. Choose JSON, CSV or Markdown and check the local download. Repeat
for each format. Export sits next to Search All Functions in both Functions layouts. With the same trial, open
Setup → Automation → Workflow Rules and click Search All Workflows to search every rule. The
Automation Map button there is labelled "Coming soon": it does not open the map, only a waitlist
popup with a static preview and a Pro upgrade prompt (Pro and Max accounts see "You're on the
list"). The map itself is not part of this submission's working features.

A one-time "What's new" card on Zoho CRM pages introduces these tools; Got it, close or any of
its links dismiss it for good.

Existing users see a dismissible account/privacy notice in the popup. Disconnect there to
clear local account tokens; existing free features continue working. Signing out does not
cancel a subscription or delete the website account. Account/billing controls are on the website.
No paid purchase or card is needed to review Export through a new account's trial.
